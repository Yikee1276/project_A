# 📘 第四课笔记：Vector 骨架与 1e6 验收

## 一、 核心知识点总结

1. **Vector 的三个核心成员**
   * `T* data_`：指向底层申请的地皮（原始内存）。
   * `size_t size_`：实际盖好的房子数量（真实存了几个元素）。
   * `size_t capacity_`：买下的地皮总坑位（最多能装几个）。
   * `std::allocator<T> alloc_`：包工头，负责买地皮/退地皮。

2. **扩容 `reserve(new_cap)`**
   * **顺序严格**：先买新地皮 -> 用 placement new 搬家 -> 手动析构旧房子 -> 退旧地皮 -> 更新 `capacity_`。
   * **边界**：`if (new_cap <= capacity_) return;` 避免缩容和无意义的搬家。
   * `reserve` **只改 `capacity_`，绝不改 `size_`**因为搬家和原本家的大小无关。

3. **装填 `push_back(value)`**
   * 满则扩容：`new_cap = (capacity_ == 0) ? 1 : capacity_ * 2;`（0 不能乘 2，必须给 1）。
   * 原地构造：`new (data_ + size_) T(value);`。
   * 状态更新：`++size_;`。

4. **析构逻辑 `~Vector()`**
   * 必须先循环调用 `data_[i].~T();` 拆掉 `size_` 个房子，再 `alloc_.deallocate` 退掉 `capacity_` 块地皮。两步缺一不可。

5. **下标访问 `operator[]`**
   * 返回引用 `T&`，使得 `v[0] = 10;` 合法，且避免无意义的拷贝。

## 二、 课堂问答回顾（你的疑惑与解答）

**Q1：`data_[i].~T();` 里的析构函数我写了吗？直接用可以吗？**
* **解答**：可以且必须直接用。如果你自定义了类，编译器会调你写的析构；如果你没写，会调编译器生成的默认空析构。即使 `T` 是 `int`，也存在合法的“伪析构函数”（什么都不做）。**必须写这行**，因为 `placement new` 造出来的对象系统不管，不手动析构会导致内部资源泄漏。

**Q2：在 `reserve` 的最后，为什么不用修改 `size_`？**
* **解答**：`reserve` 的语义仅仅是“换一块更大的地皮”（只改变 `capacity_`）。搬家前有 2 栋房子，搬到新地皮后依然只有 2 栋房子。修改 `size_` 的职责属于 `push_back`（盖一栋新房，`size_ + 1`），职责绝不能串。

**Q3：如果是空 Vector，在 `data_` 零号位建房子，代码怎么处理的？**
* **解答**：代码 `data_ + size_` 完美包容了这种情况。空 Vector 时 `size_ = 0`，此时 `data_ + 0` 就是零号位。这个表达式永远指向“下一个要盖房子的空地”，极其优雅，无需写 `if (size_ == 0)` 单独处理。
