## 一、 核心知识点总结

### 1. Vector 的底层骨架（三要素与包工头）
- `T* data_`：指向底层申请的地皮（原始内存）。
- `size_t size_`：实际盖好的房子数量（真实存了几个元素）。
- `size_t capacity_`：买下的地皮总坑位（最多能装几个）。
- `std::allocator<T> alloc_`：包工头，负责买地皮（`allocate`）和退地皮（`deallocate`）。

### 2. 内存管理与扩容逻辑
- **扩容 `reserve(new_cap)`**：顺序严格（买新地皮 -> 搬家 -> 拆旧房 -> 退旧地皮 -> 更新 `capacity_`）。边界防御：`if (new_cap <= capacity_) return;`。
- **职责死守**：`reserve` **只改 `capacity_`，绝不改 `size_`**。搬家不改变房子数量，修改 `size_` 是 `push_back` 的职责。
- **析构 `~Vector()`**：必须先循环调用 `data_[i].~T();` 拆掉 `size_` 个房子，再 `alloc_.deallocate` 退掉 `capacity_` 块地皮。两步缺一不可。

### 3. 装填与原地构造（现代 C++ 核心）
- **常规装填 `push_back(const T& value)`**：满则扩容（`new_cap = (capacity_ == 0) ? 1 : capacity_ * 2;`），原地构造 `new (data_ + size_) T(value);`，更新 `++size_;`。
- **移动语义 `push_back(T&& value)`**：接收右值（临时对象），使用 `std::move` 触发移动构造，避免深拷贝，将 O(n) 开销降为 O(1)。
- **完美转发与原地构造 `emplace_back(Args&&... args)`**：
  - **万能引用**：`Args&&...` 配合引用折叠，既能接收左值也能接收右值。
  - **完美转发**：`std::forward<Args>(args)...` 保持参数的原始左/右值属性，原汁原味地传给构造函数。
  - **极致优化**：直接在 `data_ + size_` 内存处调用构造函数，彻底消除外部临时对象的构造与移动开销。

### 4. 迭代器与访问接口
- **原生指针即迭代器**：对于连续内存，`T*` 天然满足随机访问迭代器要求。`begin()` 返回 `data_`，`end()` 返回 `data_ + size_`（永远指向下一个要盖房子的空地，完美包容空 Vector）。
- **下标访问 `operator[]`**：返回引用 `T&`，使得 `v[0] = 10;` 合法，且避免无意义的拷贝。

## 二、 课堂问答回顾（你的疑惑与解答）

**Q1：`data_[i].~T();` 里的析构函数我写了吗？直接用可以吗？**
- **解答**：可以且必须直接用。即使 `T` 是 `int`，也存在合法的“伪析构函数”（什么都不做）。**必须写这行**，因为 `placement new` 造出来的对象系统不管，不手动析构会导致内部资源泄漏。

**Q2：在 `reserve` 的最后，为什么不用修改 `size_`？**
- **解答**：`reserve` 的语义仅仅是“换一块更大的地皮”。搬家前有 2 栋房子，搬到新地皮后依然只有 2 栋房子。修改 `size_` 的职责属于 `push_back`，职责绝不能串。

**Q3：如果是空 Vector，在 `data_` 零号位建房子，代码怎么处理的？**
- **解答**：代码 `data_ + size_` 完美包容了这种情况。空 Vector 时 `size_ = 0`，此时 `data_ + 0` 就是零号位。这个表达式永远指向“下一个要盖房子的空地”，极其优雅，无需写 `if (size_ == 0)` 单独处理。

**Q4：既然 `Vector` 已经是模板 `T` 了，为什么 `emplace_back` 还要再套一层 `template <typename... Args>`？**
- **解答**：`T` 决定的是“目的地”（你要盖的房子类型），而 `Args` 决定的是“建筑材料”（砖头、水泥）。`emplace_back` 的精髓在于：绕过外部对象的构造，直接把建筑材料（`Args`）透传给构造函数，在指定的地皮上原地砌房子。

**Q5：为什么 `emplace_back` 的参数 `Args&&... args` 是右值引用，却能接收普通变量（左值）？**
- **解答**：在模板参数推导中，`Args&&` 被称为**通用引用（Universal Reference）**。它配合“引用折叠规则”，既能接收左值（折叠为 `T&`），也能接收右值（保持 `T&&`）。配合 `std::forward`，就能实现参数的“完美转发”。

## 三、 实战排错与语法避坑指南（血泪经验）

### 1. `const` 成员函数的正确位置
- **错误写法**：`const size_t size() { return size_; }` （编译器认为这是返回一个常量数字，导致与无 const 版本冲突，报 `cannot be overloaded`）。
- **正确写法**：`size_t size() const { return size_; }` （`const` 必须死死钉在参数列表括号 `)` 的后面，表示该函数承诺不修改类的成员变量）。

### 2. `operator[]` 的重载细节
- **错误写法**：`T& operator[] const(size_t index)` （`const` 不能插在 `[]` 和 `(index)` 之间）。
- **正确写法**：`const T& operator[](size_t index) const` （第一个 `const` 修饰返回值，第二个 `const` 修饰函数本身）。

### 3. `std::allocator` 的 `deallocate` 参数顺序
- **错误写法**：`alloc_.deallocate(size_, capacity_);` （相当于告诉分配器释放以数字 3 为地址的内存，直接崩溃）。
- **正确写法**：`alloc_.deallocate(data_, capacity_);` （第一个参数永远是**指针**，第二个是**当初申请的坑位数**，必须与 `allocate` 严丝合缝）。
